# Free-Tier Limits

Living reference (numbers current as of **July 2026** and volatile — LLM provider limits especially). Re-check the vendor's pricing page at implementation time rather than trusting this file blindly. The design rule this whole document serves: every row's fix is an env var or plan-tier change, never a workflow code change (`04-ADAPTER_FACTORY_GUIDE.md`). Topology context: [`06-DEPLOYMENT_TOPOLOGY.md`](./06-DEPLOYMENT_TOPOLOGY.md).

## Upgrade path

First paid tier and the trigger that should prompt it. Every migration below is a plan/key change, not an application rewrite.

| Service         | First paid tier                                                                        | Trigger                                                             |
| --------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| HF Space worker | Paid CPU upgrade, or migrate to Render $7/mo (512MB, needs lighter OCR) / $25/mo (2GB) | HF CPU-hours exhausted, Space suspended, or account is ZeroGPU-only |
| Supabase        | Pro $25/mo (8GB DB, 100GB storage, no auto-pause)                                      | DB > 500MB, or auto-pause becoming unacceptable                     |
| QStash          | Pay-as-you-go ~$1/100K messages                                                        | > 1,000 dispatches/day                                              |
| Upstash Redis   | Pay-as-you-go                                                                          | > 500K commands/month                                               |
| LLM providers   | Paid keys (carrying no-training guarantees)                                            | Daily 429s in production                                            |
| GitHub Actions  | Team $4/user/mo                                                                        | Repo goes private **and** CI usage is heavy                         |
| Sentry          | Team $26/mo                                                                            | > 5,000 errors/month                                                |
| Resend          | $20/mo (50K/month)                                                                     | > 100 emails/day                                                    |

## Reading this table

The **OpenRouter 50/day default** is the limit most likely to bite during early real usage rather than at scale — mitigated by making Groq primary and doing the $10 OpenRouter top-up early. The **HF Space ZeroGPU account restriction** is the one that can block launch outright, so it is a pre-launch verification, not a scaling concern. Everything else has slack for a solo-founder portfolio project's expected traffic.
